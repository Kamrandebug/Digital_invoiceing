# Database Migration Automation System

## 1. Centralized Migration Tracking
- **Schema**: A new `tenant_migration_logs` table has been created in the `landlord` database.
- **Model**: `TenantMigrationLog` model created to interact with the table.
- **Functionality**: Tracks `status`, `batch`, `started_at`, `completed_at`, and `error_message` for every migration run on every tenant.

## 2. Automated Migration Runner
- **Command**: `php artisan tenants:migrate`
- **Capabilities**:
  - **Batching**: Processes tenants in chunks (default: 10) to manage memory.
  - **Dry Run**: Supports `--dry-run` flag to preview execution without applying changes.
  - **Targeting**: Supports `--tenant={id}` to migrate specific tenants.
- **Execution**: Dispatches `MigrateTenantJob` for each tenant.

## 3. Robust Execution & Error Handling
- **Job**: `MigrateTenantJob` handles the actual migration logic.
- **Isolation**: Switches database context dynamically per job.
- **Logging**:
  - Captures `Artisan::output()` to logs.
  - Syncs successful migrations from the tenant's internal `migrations` table to the centralized `tenant_migration_logs`.
  - Captures exceptions and records them as `failed` in the centralized log.

## 4. Tenant Provisioning Integration
- **Service**: `TenantProvisioningService` has been updated.
- **Workflow**:
  - Creates the tenant database.
  - Runs initial migrations.
  - Immediately syncs the initial migration state to `tenant_migration_logs` so the centralized view is accurate from the start.

## 5. Usage
- **Deploying Updates**: Run `php artisan tenants:migrate` during your deployment pipeline.
- **Monitoring**: Query the `tenant_migration_logs` table to see the health of your fleet.
